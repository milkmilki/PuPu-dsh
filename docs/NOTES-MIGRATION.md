# 蒲蒲笔记接入与源码恢复

本目录是可独立构建的 `dsh-qq` 维护仓库，版本 0.1.4。来源为本机已安装的 0.1.3 插件，不依赖已删除的旧 PuPu 项目。

## 来源与范围

已从 0.1.3 发行包的 Source Map 精确恢复 16 个 TypeScript、React 和 CSS 业务文件，原始文件 SHA-256 记录在 `recovery/source-provenance.json`，原样源码保存在 `recovery/original-0.1.3/`。旧测试、依赖和文档参考升级前留档；缺失的 TypeScript 配置和构建脚本在本仓库重建。

恢复没有找回旧 Git 历史。`tests/dsh-fixture.ts` 是历史手工验收参考，仍使用旧服务，不作为 0.1.4 的验证用例；本版使用新的适配器测试和宿主实际部署检查。

0.1.3 的消息合并等待、封包、崩溃恢复、去重、图片权限和最终回复算法保留。0.1.4 只替换记忆宿主接入及其路由身份校验。

## 新接口

QQ Host 依赖同一 Cordis 环境中的 `pupuNotes` 服务：

- `state`：读取新角色目录及角色默认说话者。
- `sessionState`：查询会话实际绑定。
- `bindSession`：在已预留的空原生会话中，一次绑定角色和说话者。

接口通过 `ctx.pupuNotes.invoke()` 调用。插件不再使用旧 `pupu` 服务，没有回退旧记忆库的路径。角色和工具仍由蒲蒲笔记 Host 按会话安装，QQ 不自行拼接人物提示词。

## 身份与恢复

路由先持久化预分配会话 ID，再调用 DSH 原生创建 API；创建已提交但响应丢失时，重启复用同一会话。`creating` 路由在启动时完成恢复，只初始化会话和工具，不主动发送 QQ。

主人使用该角色在建立路由时的默认说话者名称。新联系人使用按 QQ 身份保存的稳定键及“首次昵称（QQ 号码）”，无昵称时使用“QQ 号码”；同名联系人或昵称与主人相同都不会成为同一个说话者。昵称变化不改写已有身份。旧自定义说话者必须有明确的 `speaker-name:<旧人物键>` 映射，缺失时显示错误，不从昵称推断。

路由保存 `speakerName` 后固定身份。每次投递或发送前校验新角色、双方名称、工作区和会话状态；不一致时停止路由。已有其他身份的原生会话不会被自动改绑。

升级已有旧角色 ID 时，应先完整备份，再依据笔记导入来源建立精确映射。旧会话路由存入历史；新路由使用预分配的新会话，继续使用同一角色的新笔记。不能把已经封包的旧来信改投另一会话，也不能重置已确认的发送状态。

## 验证边界

自动测试只使用临时目录、合成身份和本地模拟 OneBot/MCP。不会启动真实 QQ 网关或向实际联系人发送消息。真实 profile 的安装、启用和数据迁移由部署流程另行完成。
