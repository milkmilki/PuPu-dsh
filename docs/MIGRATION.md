# 旧记忆的完整复制迁移

旧库始终只读。预检在一个 SQLite 事务内读取全部受支持的原始记忆表，确认后为每个角色建立独立的 Markdown 笔记、来源归档和运行状态。保留原人物名称，不根据昵称猜测人物是否为当前说话者。

## 保留范围

- 人物事实及其历史状态、证据和人物关联。
- 事件线、节点、较早节点整理、别名与人物关系。
- 摘要、归档摘要、摘要整理、关系变化与原有关系记录。
- 全部现存和归档原始对话；对话附件保留原始引用。
- 提醒、整理报告、变更审计、任务、模型请求、压缩触发和引擎元数据，作为历史资料保留。
- 角色设定逐字复制为角色卡。

事实、事件和摘要正文转换成可搜索的笔记。原始对话按日期建立来源入口，逐字正文通过该笔记的 `sources` 分页读取；目前 `search` 搜索 Markdown，不直接搜索只存在来源归档中的原话。

来源记录按内容指纹保存，所有字段原样归档；笔记通过来源关系追溯历史资料。旧全文索引和向量缓存属于派生数据，不作为新系统的可写记忆库。

## 附件与任务

附件按原会话和消息严格匹配，重复引用去重，格式损坏的元数据仍保存在来源归档中。复制的是附件引用，完整记忆包不额外封装附件文件本体。

只有旧库明确记录了处理游标的会话才进入新系统的可整理对话表。缺少游标证明的历史对话仍可完整查看来源，不能自行认定全部处理过或把它们全部重新运行。

已证明游标后的对话进入新的导入整理队列。旧模型请求、提醒和触发器保留为历史，不在新宿主执行。导入成功只表示复制完成，不表示新的后台整理已经完成。

## 完整核验

正式迁移应先保存当前数据库的一致快照、旧角色配置和已有备份，再检查：

1. 逐表规范化行指纹与来源一致，包含历史记录的全部字段。
2. 全部事实、事件、摘要正文逐字出现在笔记中，角色卡与旧设定一致。
3. 所有原始资料可通过笔记来源分页读取，附件按会话和消息匹配。
4. 实际事实文本能通过笔记搜索找到，两角色保存在独立目录。
5. 重复导入没有变化，旧库及配置检查前后指纹相同。
6. 导出的完整 `.pupunotes` 包可重新导入并保留正文与来源。

私人迁移包、来源快照和实际报告单独保存，不进入 Git、插件 `.tgz` 或公开源码包。数据复制与 DSH profile 中的插件启用是两个操作；复制不会自动接管旧会话或同时运行两个身份替换插件。
