# 测试报告（开发快照）

本报告只记录已经实际运行的检查，不把“接口能启动”当成端到端通过。真实 DSH Web profile 的安装、身份替换和 UI 操作仍需在独立 profile 中完成最终验收。

## 已通过

- `node --import tsx --test tests/ui-model.test.ts`
  - 文件分页完整读取、最终换行保留、并发 revision 变化拒绝保存。
  - Markdown 相对链接限制在角色目录内；脚本、磁盘路径和越界链接不会变成可点击操作。
  - 宿主分页不前进时停止，避免 UI 死循环。
- `node --import tsx --test tests/migration.test.ts`
  - 旧 SQLite 复制导入、同名人物显式映射、重复/增量导入不覆盖 AI 编辑。
  - 精选种子包不含源对话和模型路由，校验和篡改检查有效。
  - `.pupumem` 路径穿越包在解压前拒绝。
  - 新完整/种子包往返保留笔记、原始来源和版本；源宿主的任务不会恢复运行。
  - 原 fact evidence 和消息范围可以从笔记来源读取，所有旧记录的内容指纹逐条核验。
  - 只把有可靠处理游标的未读对话登记为新任务。
  - 旧 catalog 的人设作为只读数据导入，虚拟表格式的伪装来源库被拒绝。
  - 暂存角色目录交换被中断后，恢复日志能继续完成导入。
  - 精选种子包明确勾选来源时，仅包含所选笔记能追溯的资料，不导出其他笔记的私密对话和历史版本。
  - 导入游标必须属于自己的会话，不能指向其他会话或未保存的消息。
  - 新包增量导入的补充笔记仍可查询新增原始对话，同时保留目标角色已编辑的正文。
  - ZIP 解压前预检中央目录、大小声明和本地头；拒绝 ZIP64、多卷、大小写冲突、路径穿越、文件目录冲突和超大解压声明。
  - 旧 `.pupumem` manifest 中已知的人设字段作为数据导入。
- `npm run typecheck`
  - 当前 TypeScript 源码通过；完整 `npm run check` 仍应在每次依赖或 Host 变更后重跑。

## 仍需在真实 DSH 验收

1. 用隔离 profile 安装 `.tgz`，设置页显示“蒲蒲笔记”，禁用/重启/卸载后数据和旧插件仍独立。
2. 对新会话检查实际发送的 system-role 消息：`harness:identity` 与 `deployment:persona-prefix` 被角色范围替换，原生工具、权限、工作目录和 Provider 路由仍在；角色卡只出现一次。
3. 发送真实用户输入、可见助手文本、思考、工具回执、失败尝试和压缩摘要，确认只有允许的对话进入 `dialogue`。
4. 触发自动压缩和手动 `/compact`，分别让 DSH 压缩与蒲蒲笔记整理慢、失败、取消，确认两边状态互不误标。
5. 使用同一批记忆和问题对照原始显式抽取与新笔记工具路径，比较事实、经历、摘要、来源证据和游标，而不是只比较 HTTP/MCP 成功。
6. 验证每日任务的起始目录清单、分页覆盖、部分失败恢复、重启恢复和角色 A/B 隔离。

未完成项目不会被标记为“已验证”；发布前需要保存 profile 日志、实际 prompt 快照和独立数据目录路径。
