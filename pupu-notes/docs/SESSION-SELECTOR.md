# 每个聊天窗口选择角色与说话者

0.1.1 在 DSH 原生聊天输入框旁恢复了会话选择器。角色与说话者均按 session 保存，不改变其他窗口的选择。

## 使用

1. 在 DSH 中新建空白会话。
2. 在输入框旁选择“普通助手”或已创建、已导入的角色。
3. 选择已有说话者，或选“新增说话者…”输入姓名。
4. 点击“应用到当前对话”，确认成功后开始聊天。

角色列表来自“设置 → 蒲蒲笔记”。这里只显示姓名，不显示内部身份编号。

真实对话或待处理输入出现后，双方身份固定。此时选择器显示双方姓名；“另开对话”可以选另一组角色和说话者，新对话继承原会话的工作目录，不复制历史消息。普通助手的新会话使用 DSH 原生“新建会话”。

## 一致性与恢复

Host 通过官方 `Agent.runMaintenance()` 占用空闲阶段，在重新安装角色身份和笔记工具后才同步提交绑定。切换期间到达的第一条消息留在 DSH 队列，之后才执行；已有消息时不能借 UI 或直接接口更改归属。

切换失败时恢复原角色的作用域与绑定。若原角色也暂时无法恢复，模型请求会停止；选择器展示“修复当前身份”。这个入口只重新安装已绑定的同一身份，不迁移、改写历史或替换为草稿中的人物。

选择普通助手会卸载这个插件的角色提示词和笔记工具。后续普通助手消息不进入角色笔记。角色提示词的替换、主动查笔记、压缩触发整理及每日通读逻辑保持原有流程。

## 源码位置

- `src/ui/SessionSelector.tsx`：原生选择器、说话者选择与新增姓名、状态和修复界面。
- `src/ui/index.tsx`：`conversation.input.left` 的官方 session 作用域入口。
- `src/host/session-selector.ts`：维护阶段占用、开聊锁定与同身份修复。
- `src/host/index.ts`：身份和工具作用域安装、回滚、关闭保护。
- `src/product.ts`、`src/catalog.ts`：管理接口与持久化绑定事务。
- `tests/host-selector.test.ts`、`tests/product-selector.test.ts`、`tests/ui-selector.test.ts`：隔离、竞态和修复用例。

本实现直接使用新的笔记引擎，没有接回旧版 RAG。旧 `dsh-pupu 0.1.11` 的 15 个原始 TypeScript／React／CSS 源文件另存于相邻的 `dsh-pupu-recovered` 独立仓库，供查阅；它不是新插件的运行依赖。
